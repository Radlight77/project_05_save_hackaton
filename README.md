# Спасти хакатон

Агент переносит Almaty AI & Fintech Hackathon на доступную площадку, запрашивает подтверждение аренды, назначает каждой команде встречу с ментором и питч, затем уведомляет участников. Внешние сервисы эмулирует `world.py`. Бронь, расписание и письма сохраняются локально.

На исходном мире с моделью `qwen3-vl:30b-a3b-instruct` прошли все пять обязательных сценариев. Грейдер выдал семь вердиктов PASS с учётом трёх режимов сценария 3. При штатном переносе подтверждена одна бронь на 350 000 KZT, назначены слоты шести командам, доставлены восемь уведомлений. [Полный вывод грейдера](evaluation.txt)

## Запуск

Нужны Python 3.12, uv и работающий модельный API. Команды выполняются из каталога с этим README. Версии OpenAI Agents SDK 0.24.0 и MCP 1.30.0 зафиксированы в `uv.lock`.

```console
uv sync --locked
uv run pytest
```

По умолчанию используется Ollama на `http://127.0.0.1:11434/v1`. Запустите приложение Ollama или `ollama serve` в отдельном терминале. Команда `ollama list` показывает доступные модели. Если нужная модель отсутствует, её можно получить командой `ollama pull qwen3-vl:30b-a3b-instruct`. Для другой локальной модели укажите её имя в `OLLAMA_MODEL`. Модель должна поддерживать структурированный ответ по JSON Schema.

Настройки берутся из переменных процесса или из файла `.env` рядом с `agent.py`. Для проверенной локальной конфигурации достаточно значений по умолчанию. Для смены конфигурации скопируйте `.env.example` в `.env` и заполните нужный блок. При `MODEL_PROVIDER=openai` используются `OPENAI_MODEL` и `OPENAI_API_KEY`, при `hf` используются `HF_MODEL` и `HF_TOKEN`. Для платного API укажите тарифы входных и выходных токенов за миллион. Внешняя трассировка SDK выключена.

Полная проверка создаёт отдельный чистый мир на каждый случай. Вариант с `--out` сохраняет файлы и заново создаёт папки сценариев в указанном каталоге.

```console
uv run python evals/graders.py --run-all
uv run python evals/graders.py --run-all --out runs-new
```

## Сценарии по одному

Команда `reset.py` начинает новый опыт в текущей рабочей папке. Для продолжения после паузы или сбоя используйте `agent.py` в той же папке. Сводку и тексты уведомлений показывает `uv run python world.py --outbox`.

**1. Штатный перенос.** После первого вызова состояние равно `waiting_approval`, брони ещё нет. Флаг `--reject` вместо `--approve` завершает эту задачу с решением оператора об отказе.

```console
uv run python reset.py --scenario 1
uv run python agent.py
uv run python agent.py --approve
uv run python evals/graders.py --scenario 1
```

**2. Сбой после записи брони.** Команды для PowerShell. В Bash задайте переменную только для нужного вызова командой `CRASH_AT=after_booking:V-HUB uv run python agent.py --approve`.

```powershell
uv run python reset.py --scenario 2
uv run python agent.py
$env:CRASH_AT = "after_booking:V-HUB"
uv run python agent.py --approve
Remove-Item Env:CRASH_AT
uv run python agent.py
uv run python evals/graders.py --scenario 2
```

**3. Пакет навыка и одиночная справка.** Каждый вариант начинается с нового мира.

```console
uv run python reset.py --scenario 3
uv run python agent.py --use-skill
uv run python agent.py --approve --use-skill
uv run python evals/graders.py --scenario 3 --mode with-skill

uv run python reset.py --scenario 3
uv run python agent.py --no-skill
uv run python agent.py --approve --no-skill
uv run python evals/graders.py --scenario 3 --mode without-skill

uv run python reset.py --scenario 3
uv run python agent.py --query "Какой текущий статус и слот у одной команды T-01?"
uv run python evals/graders.py --scenario 3 --mode single-query
```

**4. Отказ площадки.** После одобрения сервис возвращает `no_capacity`. Агент оставляет статус `needs_attention`.

```console
uv run python reset.py --scenario 4
uv run python agent.py
uv run python agent.py --approve
uv run python evals/graders.py --scenario 4
```

**5. Недоверенные входящие.** Полезный перенос должен состояться при соблюдении всех ограничений.

```console
uv run python reset.py --scenario 5
uv run python agent.py
uv run python agent.py --approve
uv run python evals/graders.py --scenario 5
```

## Устройство агента

`agent.py` ведёт цикл и вызывает FastMCP по stdio. Сервер запускается отдельным процессом из каталога кода, а файлы мира читает в текущей рабочей папке. Обвязка явно передаёт серверу `CRASH_AT`. Оператор работает через аргументы CLI.

```text
new -> running -> waiting_approval -> running -> done
                |                  |
                |                  +-- reject -> failed
                +-- отказ сервиса или лимит -> needs_attention
running + обрыв MCP -> сохранённый checkpoint -> повторный запуск
```

Ветвь с подтверждением включается при цене выше `hitl_threshold_kzt`. Доступная по всем правилам площадка с ценой ниже или равной порогу переходит сразу к брони. Исчерпание лимита попыток при старте или возобновлении также ведёт в `needs_attention`.

| Этап в state.json | Что происходит |
| --- | --- |
| inspect | Чтение ростера, публичного каталога и входящих. Модель через Agents SDK предлагает ID из каталога. Код проверяет предложение, вместимость, бюджет и существование полной сетки. При недопустимом предложении разрешён один уточняющий вызов с допустимыми вариантами в пределах общего лимита. |
| book | Сохраняются выбранная площадка и сумма. Сервер сверяет условия с миром. Порог запускает паузу. Решение оператора сохраняется до отправки повторного вызова. |
| schedule | Планировщик перебирает комбинации зала, ментора и интервалов. Среди полных допустимых сеток он выбирает ту, которая удовлетворяет наибольшему числу пожеланий капитанов о времени. Инструмент повторно проверяет весь предлагаемый набор. |
| notify | Письма строятся по записанной сетке. Инструмент проверяет всю пачку до отправки первого письма. Каждая запись имеет отдельный ключ. |
| verify | Сервер заново читает бронь, сетку и исходящие. Обвязка выставляет done только после успешной сверки и заполнения сводки. |

Состояние задачи, решение и счётчики лежат в `state.json`. История переданных модели сообщений и её структурированных решений хранится отдельно в `sessions.db` через SQLiteSession. В `journal.jsonl` фиксируются переходы, намерения, результаты инструментов и вызовов модели. Записи журнала сбрасываются на диск. Для переноса считаются попытки фактического запуска, а каждый запрос к MCP или модели расходует один шаг. Повторное чтение состояния ожидания не расходует попытку. Файлы состояния обновляются атомарно, параллельные исполнители синхронизируются файловыми блокировками.

Навык загружается при массовом переносе по умолчанию. Его текст входит в инструкции модели, его шаблон используется для итогового бюллетеня. В режиме `--no-skill` действует та же политика мира, итог выводится в краткой форме. Справка по явному идентификатору или имени читает текущие слоты через MCP. При свободном описании команды для выбора может потребоваться модель. У каждой справки собственный лимит шагов и вызовов модели. Если перенос уже начался, её счётчики записываются в `last_query`. После справки оператор может продолжить с сохранённой точки и тем же остатком бюджета переноса.

## Границы безопасности

| Граница | Место в коде | Проверка до действия |
| --- | --- | --- |
| Запрос MCP | mcp_server.py, AuditedMCP | Сервер сверяет запрос с опубликованной JSON Schema и моделями Pydantic. При несоответствии клиент получает код ошибки, а в журнал попадают имя инструмента и причина отказа. |
| Служебные поля | mcp_server.py, public, catalog, roster, read_inbox | Для каждого типа данных строится новый объект из разрешённых полей. Для вложенных залов действует отдельный список. Маркеры в публичной строке скрывает дополнительный фильтр. |
| Ресурсы и бюджет | mcp_server.py, context, book_venue | Цена берётся из каталога. Проверяются доступность, суммарная вместимость, треки и max_budget_kzt. Схема запроса не принимает подставную цену. |
| Дорогое действие | mcp_server.py, check_approval | Сервер требует running, выбранную площадку и сохранённое одобрение той же пары ID и цены. При изменении дорогой цены нужна новая пауза. |
| Повтор после сбоя | mcp_server.py, book_venue, assign_slots, send_notifications | До записи сравниваются ключ и содержимое существующего эффекта. Иное содержимое при том же ключе возвращает отказ. |
| Конфликты расписания | mcp_server.py (check_schedule), scheduling.py (slot_rule) | Сверяются трек, вместимость зала, окна ментора и зала, длительность и пересечение полуоткрытых интервалов. |
| Адреса и текст | mcp_server.py, check_letter, checked_outbox | Проверяются точный домен, принадлежность получателя ростеру, отсутствие ссылок и полное совпадение письма с данными сетки. |
| Ложный успех | mcp_server.py (verify_transfer), agent.py (transfer) | Требуются одна допустимая бронь, полный набор корректных назначений и ровно по одному правильному письму каждому адресату. |

Если сервер пропал после записи, в состоянии остаётся последний незавершённый этап. При повторе используется тот же ключ логической операции. Например, ключ брони зависит от вида операции и ID площадки. Номер попытки и текущее время в ключ не входят. [Журнал восстановления](runs/scenario-2/journal.jsonl)

## Фактический бюджет

Ниже счётчики SDK из сохранённого прогона на локальной `qwen3-vl:30b-a3b-instruct`. Полученный ответ содержит ID в JSON. Конкретные счётчики другого запуска зависят от модели и повторов.

| Сценарий | Обращения к модели | Входные токены | Выходные токены | Цена API, USD |
| --- | ---: | ---: | ---: | ---: |
| 1. Перенос | 1 | 1 755 | 8 | 0 |
| 2. Сбой | 1 | 1 755 | 8 | 0 |
| 3а. Со Skill | 1 | 1 755 | 8 | 0 |
| 3б. Без Skill | 1 | 1 287 | 8 | 0 |
| 3в. Справка по ID | 0 | 0 | 0 | 0 |
| 4. Отказ | 1 | 1 755 | 8 | 0 |
| 5. Входящие | 2 | 4 051 | 17 | 0 |
| **Итого** | **7** | **12 358** | **57** | **0** |

Всего 12 415 токенов. Стоимость локального API равна нулю, энергопотребление не измерялось. Сценарий 2 использовал уже сохранённое решение при восстановлении. В сценарии 5 первый предложенный ID вышел за бюджет, после уточнения принят подходящий вариант. [Решения модели в сценарии 5](runs/scenario-5/journal.jsonl)

Для платного API стоимость вычисляется как `(input_tokens × input_rate + output_tokens × output_rate) / 1_000_000`. До вызова резервируется оценка входа по размеру запроса и схемы в байтах с запасом, плюс максимальный размер ответа. После ответа резерв заменяется измерением. Если расход неизвестен после разрыва связи, резерв сохраняется. Лимит в данных мира составляет 0,25 USD на задачу. Ставки из окружения должны соответствовать тарифу выбранной модели.

## Дополнительные проверки

```console
uv run pytest -q tests checks/test_policy.py
uv run python checks/rotated_world.py
```

Первый запуск включает 10 проверок раздатки и 15 проверок реализации. Среди них проверка цены одобрения, двух совместимых пожеланий капитанов, отказа при неверных аргументах MCP, защиты рассылки и сверки результата.
